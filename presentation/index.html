Project 1 • Step 1: Proposal Intake & Eligibility Screening

Student Registration, Automated Team Validation, Defect Loops, and Coordinator Gatekeeping

Camunda Diagram: Step 1 (Intake & Screening)
Start: Team Decides to Submit User: Submit Project Proposal Service: Validate Form & Team Rules Timer: 14d Intake Window (F4) Error: Invalid Team (F2) XOR: Validation Result?
Flow Explanation from Diagram
The workflow initiates at Team Decides to Submit Proposal. The student lead submits proposal metadata via a Camunda form. A system Service Task automatically validates team constraints (size 2-4, student uniqueness across teams). If validation fails due to missing fields, a retry loop is triggered. Once valid, the Coordinator conducts scope and prerequisite screening.
Task Types Used
User Task
Submit Project Proposal: Student team fills title, domain, abstracts, and roll numbers.
Service Task
Validate Form & Team Rules (F1, F2): Java/REST delegate verifying academic eligibility and team integrity.
User Task
Resolve Validation Defect (F1): Student lead corrects incomplete fields within retry limit.
User Task
Screen Proposal Scope & Eligibility: Coordinator approves or rejects topic relevance.
Gateways & Intermediate Events
Exclusive XOR
Validation Result?: Directs flow to Valid, Incomplete Fields, or Retries Exceeded.
Exclusive XOR
Retry Count < 2? (F1): Guards loop against infinite defect resubmissions.
Boundary Timer
Deadline Approaching/Lapsed (F4): 14-day timer routing late teams to Coordinator review.
Boundary Error
System/DB Error (F10): Catches DB connection failures & triggers Fallback Logger.
Critical vs. Alternate Paths
Happy Path: Valid submission → Passes rule checks → Coordinator approves scope → Moves to Plagiarism Check.
Critical Alternate (F1): Incomplete fields trigger student retry loop (permitted up to 2 times).
Alternate Rejection (F2): Severe rule violation (e.g., student on two teams) routes to Error End Event "Rejected: Invalid Team Composition".

Project 1 • Step 2: Plagiarism & Committee Evaluation

Similarity Engine, Coordinator Duplicate Review, Panel Scoring, and Emergency HoD Escalation

Camunda Diagram: Step 2 (Plagiarism & Evaluation)
Service: Check Duplicate & Plagiarism User: Evaluate Proposal (Committee) User: HoD Emergency Review (F7) Timer: 3-Day SLA Warning Timer: 7-Day SLA Breached XOR: Committee Verdict?
Flow Explanation from Diagram
An automated Service Task scans the proposal against past project archives. If similarity > 30%, the Coordinator reviews the match report to determine if it is duplicate or permissible. Once cleared, the Review Committee scores the proposal across novelty and feasibility. If the panel exceeds SLA, an interrupting timer escalates the evaluation to the Head of Department (HoD).
Task Types Used
Service Task
Check Duplicate Topic & Plagiarism (F3): Computes text similarity against institutional repositories.
User Task
Review Plagiarism / Match Report (F3): Coordinator reviews high-match alerts.
User Task
Evaluate Proposal (Review Committee): 3-member faculty panel assigns rubric scores.
User Task
HoD Emergency Review & Direct Decision (F7): Executive sign-off if committee breaches SLA.
Gateways & Intermediate Events
Exclusive XOR
Similarity > 30%? (F3): Routes clean proposals directly to committee; high match to coordinator.
Exclusive XOR
Committee Verdict?: Tri-way branch: Approved, Revision Needed (F5), or Rejected (F6).
Non-Interrupting Timer
3-Day SLA Warning (F7): Sends reminder alert to committee members.
Interrupting Timer
7-Day SLA Breached (F7): Escalates task directly to HoD lane.
Critical vs. Alternate Paths
Happy Path: Low similarity (≤30%) → Unanimous Committee Approval → Passes directly to Guide Allocation.
Critical Alternate (F5): Revision cycle: Student given 7 days to update proposal (max 2 iterations allowed).
Rejection & Resubmission (F6): First rejection allows 1 new topic submission; second rejection triggers Hard Reject End Event.

Project 1 • Step 3: DMN Guide Allocation & Quota Rollback

Business Rules Table, Invitation Lifecycle, Coordinator Override, and Transactional Compensation

Camunda Diagram: Step 3 (Guide Allocation Sub-Process)
Business Rule: DMN Guide Matching Send: Send Allocation Request User: Accept/Decline (Guide) Timer: 3-Day Guide Timeout (F9) Comp: Free Guide Quota (F11) XOR: Guide Attempts < 3?
Flow Explanation from Diagram
Approved projects enter the Faculty Guide Allocation Sub-Process. A Business Rule Task evaluates guide_allocation_rules.dmn matching topic domain (AI/ML, Web, IoT, Cloud) to faculty research rank and ensures workload < 3 teams. If matched, a slot is reserved and an invitation sent. The faculty guide has 3 days to accept. If declined or timed out, the system retries with backup guides (max 3) before falling back to manual coordinator assignment.
Task Types Used
Business Rule Task
Evaluate Guide Availability & Domain Match (F8): Executes DMN decision table.
Send Task
Send Allocation Request to Guide: Dispatches invitation email to faculty inbox.
User Task
Accept / Decline Allocation Request (F9): Faculty guide confirms or rejects mentorship.
User Task
Coordinator Manual Allocation (F8): Manual assignment when capacity full or retries exhausted.
Gateways & Intermediate Events
Exclusive XOR
Guide Available?: Match found → Reserve slot; None found → Manual allocation.
Exclusive XOR
Guide Attempts < 3? (F9): Bounded loop controlling automated reassignment attempts.
Boundary Timer
3-Day Guide Timeout (F9): Auto-escalates unacknowledged invites to the next guide.
Compensation Throw
Compensate Guide Quota (F11): Triggered by student withdrawal message; decrements guide workload.
Critical vs. Alternate Paths
Happy Path: DMN finds top-ranked faculty → Guide accepts in 24h → Slot recorded → Confirmed.
Critical Alternate (F8/F9): Guide declines or 3-day timer expires → System loops to backup guide (max 3).
Withdrawal Compensation (F11): Team withdrawal event → Rollback handler frees faculty quota in DB.

Project 2 • Step 1: Intake & 4-Way Parallel Due Diligence

Document Completeness, Fork/Join Gateway Synchronization, and Anti-Financial Crime Protection

Camunda Diagram: Step 1 (Intake & Parallel Verifications)
Message Start: Loan Application Parallel Split: 4 Verification Streams Service: Automated KYC & Bureau Pull Timer: 7-Day Resubmission Window (L1) Error: Bureau API Timeout (L4) Terminate: AML Sanction Reject (L3)
Flow Explanation from Diagram
Applicant submits loan application from external pool. Business Rule checks document completeness. Once valid, a Parallel Gateway Split branches into 4 simultaneous tracks: (1) Automated e-KYC, (2) Credit Bureau pull, (3) AML watchlist screening, and (4) Income verification. An AND Join Barrier synchronizes all 4 streams before passing verified records to underwriting.
Task Types Used
Business Rule Task
Check Document Completeness (L1): Validates identity, income, and property records.
Service Tasks
Automated KYC, Bureau Pull & AML Screening: Parallel REST delegates querying external systems.
User Task
Verify Income & Employer (L6): Credit analyst inspects bank statements.
User Task
Manual KYC & Bio Verification (L2): Compliance officer inspects biometric mismatches.
Gateways & Intermediate Events
Parallel Gateways
Fork Streams & Synchronize Verifications: Ensures all 4 checks complete before underwriting.
Boundary Timer
7-Day Resubmission Window Lapsed (L1): Auto-lapses stale missing document tasks.
Boundary Error
Bureau API Timeout (L4): Catches 504 gateway failures & triggers 3-retry fallback.
Terminate End
Terminated: Fraud/Sanction Reject (L3): Positive AML match instantly kills all concurrent tokens.
Critical vs. Alternate Paths
Happy Path: Complete docs → All 4 parallel checks clear in <45 seconds → Enters DMN Scoring.
Critical Alternate (L2): Biometric KYC mismatch routes to video-KYC manual review without failing process.
Sanction Kill Switch (L3): AML watchlist hit terminates the entire process immediately for compliance.

Project 2 • Step 2: DMN Risk Scoring & Credit Underwriting

Multi-Table Credit Matrix, Counter-Offer Negotiation, High-Value Escalation, and Collateral Inspection

Camunda Diagram: Step 2 (DMN Scoring & Underwriting)
Business Rule: DMN Risk Tier Calculation User: Underwriter Review & Sanction User: Senior Committee Deliberation (L7) User: Formulate Counter-Offer (L5) XOR: Credit Policy Route? XOR: Title & LTV Acceptable? (L8)
Flow Explanation from Diagram
A Business Rule Task evaluates loan_eligibility_rules.dmn across CIBIL score (≥750), Debt-to-Income (≤40%), and loan quantum. The decision routes into: Standard Approval (Tier A), Counter-Offer (High DTI requiring guarantor or lower principal), Borderline Referral to Credit Underwriter, or Outright Rejection. For secured loans, collateral valuation confirms LTV ≤ 80% before approval.
Task Types Used
Business Rule Task
DMN Eligibility & Risk Tier Calculation (L5, L6, L7): Evaluates credit risk table.
User Task
Credit Underwriter Review & Sanction: Human underwriting for discretionary approvals.
User Task
Senior Credit Committee Deliberation (L7): Dual-signoff for exposures > $100,000.
User Task
Collateral Inspection & Title Verification (L8): Legal property valuation check.
Gateways & Intermediate Events
Exclusive XOR
Credit Policy Route?: Multi-way branch: Approved, Borderline / > Limit, High DTI, or Rejected.
Exclusive XOR
Counter-Offer Accepted?: Applicant acceptance moves to approval; refusal ends process.
Exclusive XOR
Title & LTV Acceptable? (L8): Clear title moves to sanction letter; defects route to rejection.
Critical vs. Alternate Paths
Happy Path: Tier A risk score → Auto-sanction → Generates Sanction Letter & Repayment Schedule.
Critical Alternate (L5/L6): High DTI triggers Counter-Offer (reduced principal or guarantor requirement).
Committee Escalation (L7): High-exposure loans (> $100k) escalate to Senior Credit Committee.
Defective Title (L8): Collateral encumbrance or LTV > 80% triggers Defective Title rejection.

Project 2 • Step 3: Offer Acceptance, E-Sign & CBS Disbursement

Message Choreography, 48h Legal Signature SLA, Core Banking Sub-Process, and Reversal Compensation

Camunda Diagram: Step 3 (Offer, E-Sign & Disbursement)
Send: Dispatch Loan Offer Receive: Receive Offer Decision User: E-Sign Loan Agreement Timer: 15-Day Offer Validity (L9) Timer: 48h E-Sign Timeout (L11) Comp: Refund Fees & Release Holds (L10) Error: Gateway Error Hold (L12)
Flow Explanation from Diagram
Bank sends formal Sanction Letter to the Applicant via a Send Task. The applicant has 15 days to accept, followed by 48 hours to complete biometric digital signature. On signing, the Disbursement Sub-Process triggers: penny-drop bank verification, core ledger opening, and NEFT/RTGS transfer. If the payment gateway errors out, funds are held for Ops remediation.
Task Types Used
Send Task
Dispatch Loan Offer to Applicant: Dispatches binding contract and amortization schedule.
Receive Task
Receive Applicant Offer Decision (L9, L10): Waits for customer digital handshake.
User Task
E-Sign Loan Agreement (L11): Aadhaar e-Sign or cryptographic contract signing.
Service Tasks
Disbursement Sub-Process: Penny drop, CBS ledger creation, NEFT transfer.
Gateways & Intermediate Events
Boundary Timer
15-Day Offer Validity Lapsed (L9): Releases credit line reservation on expiry.
Boundary Timer
48h E-Sign Timeout (L11): Cancels offer if agreement not executed within SLA.
Compensation Throw
Compensate Processing Fee & Release Holds (L10): Refunds fee if applicant withdraws.
Boundary Error
Payment Gateway Error (L12): Catches 502 gateway error & routes to Hold Funds Ops queue.
Critical vs. Alternate Paths
Happy Path: Accepted in <24h → E-Signed → CBS ledger opened → Automated fund transfer confirmed.
Payment Gateway Hold (L12): CBS API timeout triggers safe hold queue; ops reconciles without duplicate debit.
Applicant Withdrawal (L10): Intermediate compensation event refunds origination fees to applicant.

BPMN 2.0 Architectural Synthesis & Best Practices

Comparative Technical Matrix: Notation Taxonomy, Resiliency Patterns, and Production Readiness

Constructs Taxonomy
Task Types
P1 uses User, Service, Business Rule, and Send Tasks. P2 additionally leverages Receive and Script Tasks.
Gateways
P1 uses Exclusive (XOR) routing. P2 uses Parallel (AND) Split/Join synchronization alongside Exclusive gateways.
Timers & Events
Non-interrupting reminders (3d), interrupting deadlines (14d, 7d, 48h, 15d), error catches, and terminate end events.
Fault Tolerance & Compensation
Compensation Handlers
Both models utilize BPMN Intermediate Compensation Throw and Event Sub-Process handlers to undo state changes (P1: Guide quota rollback; P2: Origination fee refund).
Loop Limiting
Enforces finite loops: P1 caps revisions at 2 and guide invites at 3; P2 caps counter-offers at 1 to prevent deadlock.
API Outage Recovery
Bureau and Payment API timeouts (L4, L12) catch 502/504 errors and route to bounded retry and hold queues.
Camunda 7 Production Readiness
Engine Compliance
100% compliant with OMG BPMN 2.0 XML and DMN 1.3 schemas; zero sequence flow or execution listener errors.
DMN Separation
Business rules externalized into standalone DMN tables, allowing business policy updates without redeploying workflows.
Human Form Integration
Production Camunda forms embedded for student submission, committee review, loan intake, and underwriting.
