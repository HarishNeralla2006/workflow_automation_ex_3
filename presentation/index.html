Project 1: Problem Statement & Boundaries

Assignment 1 • Student Project Approval & Allocation System (Official Specification)

Official Problem Statement (From Assignment Specification)
"A department runs a final-year project programme. Every student team must submit a project proposal. The proposal is screened, reviewed by a committee, and, once approved, a faculty guide is allocated. The process ends when the guide formally accepts the team and the student is notified."
Process Boundaries
Starts when: A student team decides to submit a project proposal.
Ends when: A guide is allocated and confirmed, or proposal is closed as rejected / lapsed.
Participants (5 Swimlanes)
1. Student / Team • 2. Project Coordinator • 3. Review Committee (incl. HoD) • 4. Faculty Guide • 5. Project Management System.
Critical Failures Addressed
F1–F2: Form & team rule breaches • F3: Duplicate topics • F4: 14d deadline • F5–F7: Revision loops & SLA delay • F8–F11: Guide capacity, timeouts & withdrawal.
Manual System Pain Points & Risks
  • • Duplicate Topics: Multiple teams choose identical projects unnoticed.
  • • Invalid Teams: Students apply alone or in groups of 5+, violating departmental guidelines.
  • • Evaluation Gridlock: Committee reviews take weeks with zero SLA tracking or escalations.
  • • Faculty Burnout: Popular professors get overloaded; junior faculty get 0 allocations.
Camunda BPMN Automated Architecture
  • • Automated Service Task: Checks team size (2–4) and student roll number uniqueness instantly.
  • • Plagiarism Engine: Flags topic similarity exceeding 30% threshold before committee review.
  • • Strict Boundary Timers: 3-day reminder + 7-day HoD emergency escalation timers.
  • • DMN Guide Matching: Domain matching + 3-project quota limit with transactional rollback.

Project 2: Problem Statement & Boundaries

Assignment 3 • Loan Origination & Approval System (Official Specification)

Official Problem Statement (From Assignment Specification)
"A bank handles personal and secured loan applications. An application passes through document checks, identity verification, credit assessment, underwriting, offer and acceptance, and finally disbursement. The model must show both the normal approval flow and every point at which an application can stall, be rejected or be cancelled."
Process Boundaries
Starts when: Applicant submits a loan application with supporting documents.
Ends when: Loan is disbursed, or application is rejected, withdrawn or has lapsed.
Participants (2 Pools / 4 Lanes)
1. Applicant (External Pool) • 2. Loan Officer • 3. Underwriter / Credit Committee • 4. Fraud & Compliance Team • 5. Operations & Core Banking • 6. Credit Bureau (External Pool).
Critical Failures Addressed
L1: Incomplete docs • L2: KYC mismatch • L3: AML/Fraud kill • L4: Bureau API down • L5–L8: DTI/Credit/Title counter-offers • L9–L12: Timeouts, withdrawal & CBS recovery.
Manual Banking Pain Points & Risks
  • • 2 to 3 Week Turnaround: Sequential verification creates massive customer drop-off.
  • • Delayed Fraud Checks: Sanctions screening happens late, wasting manual underwriter effort.
  • • Rigid Declines: High DTI applicants get rejected outright instead of receiving counter-terms.
  • • Disbursement Glitches: Gateway timeouts risk duplicate debits or un-audited ledger balances.
Camunda BPMN Automated Architecture
  • • 4-Way Parallel Due Diligence: KYC, Bureau, AML & Income execute in parallel in < 45 seconds.
  • • AML Kill Switch: Sanctions hit terminates all active parallel tokens immediately.
  • • DMN Counter-Offers: Automated counter-offer path preserves customer relationships dynamically.
  • • Transactional Sub-Process: CBS disbursement with operational hold and fee reversal.
