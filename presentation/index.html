Project 1 • BPMN Elements Master Key (The Visual Alphabet)

Understand Every Task Type, Gateway, and Boundary Event Before Inspecting the Diagram

👤
User Task
Why used: Requires human cognition, subjective scoring, or manual intervention (e.g. Student Proposal, Committee Scoring, Coordinator Screening).
Camunda Execution: Emits task to Camunda Tasklist UI; pauses process token until form is submitted.
⚙️
Service Task
Why used: Fully automated computational logic that executes in milliseconds without humans (e.g. Team Rule Validation, Plagiarism Engine, Database Logging).
Camunda Execution: Invokes Java Delegate / REST API worker; automatically advances token upon completion.
📋
Business Rule Task
Why used: Executes complex decision logic separated from workflow code (e.g. matching project domain to faculty expertise and quota limits).
Camunda Execution: Evaluates DMN 1.3 Decision Table (`guide_allocation_rules.dmn`) using First-hit policy.
🔀
Exclusive Gateway (XOR)
Why used: Decision fork where exactly ONE mutually exclusive path is chosen based on boolean conditions (e.g. Valid vs Invalid, Approved vs Revision).
Camunda Execution: Evaluates conditional expressions on outgoing sequence flows; selects first matching flow.
⏱️
Boundary Timer Event
Why used: Enforces SLAs and prevents tasks from hanging forever (14d intake deadline, 3d panel reminder, 7d HoD escalation, 3d guide response).
Camunda Execution: Camunda Job Executor sets cron/duration timer; fires interrupt or non-interrupt flow on expiry.
↩️
Compensation Event
Why used: Business rollback handler. If a student team withdraws after allocation, compensation automatically restores the professor's quota.
Camunda Execution: Intermediate Compensation Throw event calls attached compensation boundary activity to undo state.

Business Rules Table (loan_eligibility_rules.dmn) • Hit Policy: First

Camunda DMN Table: Credit Scoring & Risk Tier
Hit Policy: First 3 Input Columns 3 Output Columns Deterministic Risk Routing
How the Credit Engine Decides
Camunda evaluates Credit Score (CIBIL), Debt-to-Income (DTI), and Loan Quantum in real-time to assign risk grade and determine whether human intervention is needed.
Rule Breakdown (When → Then)
Rule 1: Tier A Prime
Credit Score ≥ 750 + DTI ≤ 40% + Loan ≤ $50k → Auto-Approve (Rate: 8.5%).
Rule 2: Tier B Near-Prime
Credit Score 680–749 + DTI ≤ 45% → Underwriter Review (Rate: 10.2%).
Rule 3: High DTI Counter
Credit Score ≥ 700 + DTI > 45% → Counter-Offer (Reduced principal or guarantor required).
Rule 4: High Value
Loan Amount > $100k → Senior Credit Committee dual authorization.
Rule 5: Sub-Prime Decline
Credit Score < 650 or DTI > 60% → Immediate Decline.
🎤 Presenter Script (Say this out loud)

Project 2 • BPMN Elements Master Key (The Visual Alphabet)

Understand Every Task Type, Parallel Gateway, and Terminate Event Before Inspecting the Diagram

➕
Parallel Gateway (AND)
Why used: Forks process into 4 concurrent verification streams (KYC, Bureau, AML, Income) and waits as a join barrier until ALL 4 finish.
Camunda Execution: Spawns 4 concurrent execution tokens; join gateway synchronizes tokens before continuing.
✉️
Send & Receive Tasks
Why used: Asynchronous B2C messaging between Bank pool and Applicant pool (Dispatch Loan Offer & Await Customer Handshake).
Camunda Execution: Send Task publishes message event; Receive Task subscribes to correlation ID matching customer.
🛑
Terminate End Event
Why used: Anti-Money Laundering (AML) kill switch! If a sanctions hit occurs, it terminates ALL active parallel tokens immediately.
Camunda Execution: Instantly destroys the entire root process instance and cancels all running tasks across lanes.
⚡
Error Boundary Event
Why used: Catches 502/504 REST timeouts from external Credit Bureau or Payment Gateways and triggers automated retry loops.
Camunda Execution: Intercepts BPMN Error codes (`BPMN_ERR_BUREAU_DOWN`) and diverts flow to retry delegate.
📦
Transactional Sub-Process
Why used: Wraps penny-drop validation, Core Banking ledger creation, and NEFT transfer in an ACID-safe boundary.
Camunda Execution: If payment fails, all internal steps roll back and route to an Operations hold queue.
↩️
Compensation Handler
Why used: If applicant cancels after sanction letter issuance, compensation refunds their $150 processing fee automatically.
Camunda Execution: Executes attached compensation service task to credit customer account and close ledger.
🎤 Presenter Script (Say this out loud)
"Take special note of the Terminate End Event vs. an ordinary End Event: If someone is flagged on an international terrorist watchlist (AML), an ordinary end event would only close that one branch while the other 3 branches continue! The Terminate End Event kills the entire loan instance instantly across all lanes."

Master Architecture Synthesis & Viva Defense Checklist

Ready-Made Answers to Common Evaluator & Professor Questions

Q: Why Use DMN Instead of Code?

Answer: Hardcoding if-else statements in Java requires recompiling and redeploying the entire workflow for every policy change. DMN externalizes decision rules into a visual table that risk managers or academic chairs can edit directly at runtime without redeployment.

Q: How Are Loops Prevented?

Answer: Both models enforce finite iteration guards using retry counter gateways. Project 1 restricts revision cycles to ≤ 2 and guide invitations to ≤ 3. Project 2 restricts counter-offers to ≤ 1. If limits are exceeded, the process routes to an executive escalation or rejection.

Q: What is Compensation in BPMN?

Answer: Unlike an error catch that aborts a task, BPMN Compensation performs business state rollback for already-completed activities. When a student withdraws or a loan is cancelled, compensation automatically frees reserved guide quotas and refunds origination fees.
