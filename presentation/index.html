Project 1: Student Project Approval & Allocation

Camunda Process Architecture across 5 Departmental Swimlanes with Integrated DMN Decision Rules

5-Lane Collaboration Pool

Strict separation of responsibilities mapped across academic organizational hierarchies:

1. Student Lane
Proposal submission, revision updates, resubmission, and project withdrawal.
2. Coordinator Lane
Team compliance screening, plagiarism review, and manual guide allocation.
3. Committee & Guide Lanes
Evaluation panel scoring; Faculty guides accept/decline assigned project slots.
4. HoD Lane
High-level intervention for overdue reviews and exhausted guide allocations.
Governance & SLA Controls

Automated timers prevent academic gridlock across the semester cycle:

Intake Deadline Timer (F4)
14-day strict window; late submissions trigger automatic rejection termination.
Evaluation SLA Timer (F7)
Non-interrupting 3-day reminder to committee; interrupting 7-day HoD escalation.
Guide Response Timer (F9)
3 business days for faculty to respond before auto-reassigning to next faculty.
DMN Decision Logic

Externalized guide allocation business rules table (guide_allocation_rules.dmn) using First hit policy:

Domain Specialization Match
Matches Project Domain (AI/ML, Web, IoT, Cloud) to Department Faculty Research.
Workload Quota Cap
Enforces maximum 3 projects per professor to ensure high mentorship quality.
Academic Priority
Allocates high GPA student teams to senior subject specialists first.

Project 1 • Step 1: Proposal Intake & Screening

Flow Architecture, BPMN Elements, and Exception Topologies for Initial Project Onboarding

Step Flow

Process starts when student team submits project title, domain, abstracts, and member details. Automated validation checks team size (2-4 students) and academic prerequisites before the Coordinator conducts initial screening.

Trigger
Start Event: "Proposal Submitted"
Hand-off
Coordinator approves → Service task triggers automated plagiarism similarity check.
Task Types Used

Hybrid human-automated execution ensuring verified application data:

User Task
"Submit Project Proposal" (Student) - Web form capturing team & synopsis.
Service Task
"Validate Team Eligibility" - Java/REST delegate verifying CGPA & course credits.
User Task
"Initial Screening" (Coordinator) - Approves scope relevance or flags invalid team.
Gateways & Events
Exclusive Gateways (XOR)
"Eligibility Passed?" (Pass / Fail)
"Screening Passed?" (Approved / Resubmit / Reject)
Boundary Timer Event (F4)
14-Day Intake Deadline attached to submission phase; cancels lingering submissions.
Boundary Error Event (F10)
Catches student resubmission counter > 2 to prevent endless re-evaluations.
Paths & Exceptions
Happy Path: Valid team → Eligible → Coordinator approves → Moves to Plagiarism Check.
Critical Alternate (F1): Resubmission loop triggered when initial info incomplete (retry count ≤ 2).
Alternate Rejection (F2): Invalid team composition or >2 retries triggers Rejection End Event.
Time-Out Drop (F4): 14-day timer fires → Application dropped due to semester deadline.

Project 1 • Step 2: Plagiarism & Committee Evaluation

Academic Integrity Verification, Faculty Scoring, Revision Control, and Emergency Escalation

Step Flow

An automated similarity engine checks the abstract against previous repositories. If similarity > 30%, coordinator reviews for duplicate flags. Once clear, the 3-member Review Committee evaluates feasibility, methodology, and scope.

Input / Output
Clean Screening → Committee Verdict: Approved / Major Revision / Rejected
Task Types Used
Service Task
"Automated Similarity Check" - Queries Turnitin/Internal database for overlap score.
User Task
"Plagiarism Review" (Coordinator) - Manual adjudication if match > 30%.
User Task
"Evaluate Proposal" (Review Committee) - Panel records rubric scores.
User Task
"Emergency HoD Review" (HoD) - Invoked if committee evaluation exceeds SLA.
Gateways & Events
Exclusive Gateways (XOR)
"Similarity ≤ 30%?"
"Duplicate Found?"
"Committee Verdict?" (Approve / Revise / Reject)
"Revision Count < 2?"
Boundary Timer (F7)
Non-interrupting 3-Day reminder to panel; Interrupting 7-Day timer escalates task directly to HoD.
Paths & Exceptions
Happy Path: Similarity ≤ 30% → Unanimous Committee Approval → Triggers Guide Allocation.
Critical Alternate (F5): Revision cycle; students granted 7 days to update proposal (max 2 iterations).
Alternate Rejection (F6): Fatal plagiarism (>30% duplicate) or Committee Rejection with 1 resubmit allowed.
Escalation Path (F7): 7-day SLA expiry triggers HoD override to unblock process.

Project 1 • Step 3: Guide Allocation & Compensation

DMN Business Rules, Faculty Invitation Loop, Coordinator Fallback, and Quota Compensation

Step Flow

Approved project enters Guide Allocation sub-process. The DMN table evaluates project domain and guide workload caps to recommend faculty. The guide has 3 days to accept. If rejected, alternate guides are invited up to 3 times before manual coordinator override.

Completion
Guide accepts → Quota committed → Confirmation dispatched → End Event.
Task Types Used
Business Rule Task
"Execute Guide Matching DMN" - Evaluates domain fit and 3-student quota cap.
Send Task
"Send Invitation to Guide" - Dispatches invitation notification to faculty email.
User Task
"Accept or Decline Request" (Guide) - Faculty accepts or rejects slot.
User Task
"Manual Guide Allocation" (Coordinator) - Invoked when 3 invites are exhausted.
Gateways & Events
Exclusive Gateways (XOR)
"Guide Accepted?" (Yes / No)
"Guide Attempts < 3?" (Loop / Fallback)
Boundary Timer (F9)
3-Day timeout on guide response; auto-triggers next faculty invite on expiry.
Intermediate Compensation Throw (F11)
Triggered if team withdraws after allocation; decrements guide workload count.
Paths & Compensation
Happy Path: DMN selects primary guide → Guide accepts in <3 days → Project Allocation finalized.
Critical Alternate (F8): First choice declines or 3-day timer lapses → System invites backup candidate.
Exhaustion Fallback (F9): 3 successive declines → Coordinator manually assigns available guide.
Compensation Flow (F11): Team withdrawal message → Rollback handler restores guide quota in DB.

Project 2 • Step 1: Intake & 4-Way Parallel Due Diligence

Document Completeness, Parallel API Orchestration, and Anti-Financial Crime Protection

Step Flow

Applicant submits loan documents. DMN validates completeness. Once complete, a Parallel Split Gateway forks into 4 simultaneous verification tracks: e-KYC, Credit Bureau (CIBIL/Equifax), AML Sanction Screening, and Income Assessment. All 4 must join before underwriting.

Trigger
Message Start: "Loan Application Received"
Task Types Used
Business Rule Task
"Verify Document Completeness" - DMN table checking ID, Proof of Income, Property docs.
Service Tasks (Parallel)
• "e-KYC Verification" (UIDAI/Govt API)
• "Credit Bureau Pull" (CIBIL/Equifax)
• "AML & Watchlist Screening" (Sanctions API)
User Tasks
• "Income Assessment" (Credit Analyst)
• "Manual KYC Review" (Compliance Officer)
Gateways & Events
Parallel Gateways (AND)
Fork Split → 4 Verification Streams → Synchronizing Join Barrier.
Boundary Timer (L1)
7-Day timer for missing documents; auto-lapses stale applications.
Error Boundary Event (L4)
Credit Bureau 504 Timeout; catches API outage and retries up to 3 times.
Terminate End Event (L3)
AML match instantly kills all concurrent branches for regulatory compliance.
Paths & Exceptions
Happy Path: Docs complete → 4 parallel streams verify successfully in <45s → Enters DMN Scoring.
Critical Alternate (L2): Automated biometric KYC fails → Routes to Manual Video-KYC Review.
Sanctions Kill (L3): AML positive flag → Triggers Terminate Event, freezes file, alerts compliance.
Bureau API Timeout (L4): 3 failed retries routes to offline bureau queue without failing process.

Project 2 • Step 2: DMN Risk Scoring & Underwriting

Multi-Table Credit Decision Matrix, Counter-Offer Negotiation, and Committee Escalation

Step Flow

The DMN engine evaluates CIBIL score, Debt-to-Income (DTI), loan amount, and collateral LTV. Results branch into: Auto-Approve, Manual Underwriter Referral, Counter-Offer (reduced principal or higher rate), or Outright Rejection.

Input Parameters
Credit Score (≥750), DTI (≤40%), Loan Amount (<$100k), Collateral LTV (≤80%).
Task Types Used
Business Rule Task
"Execute Loan Eligibility DMN" - Evaluates risk grade (Tier A/B/C/Decline).
User Task
"Underwriter Assessment" - Manual review for borderline credit scores (650-749).
User Task
"Senior Credit Committee" - Dual-signoff for loan exposures exceeding $100,000.
User Task
"Prepare Counter-Offer" - Formulates adjusted terms when DTI > 40%.
Gateways & Events
Exclusive Gateways (XOR)
"Risk Category?" (Approve / Refer / Counter / Reject)
"Loan Amount > $100k?" (Committee vs Underwriter)
"Counter-Offer Accepted?" (Yes / No)
"Counter-Offer Count < 1?" (Prevent infinite loops)
Boundary Timer (L7)
48-Hour SLA on Senior Committee approval; escalates to Chief Risk Officer.
Paths & Exceptions
Happy Path: DMN returns Tier A → Instant Auto-Approval → Generates Sanction Letter.
Critical Alternate (L5/L6): Counter-offer negotiation when DTI > 45% (capped at 1 counter-proposal).
High-Value Branch (L7): Amount > $100k escalates to Committee with strict 48-hour SLA timer.
Collateral Rejection (L8): Valuation reveals title defect or LTV > 80% → Formal Rejection Notice.

Project 2 • Step 3: Offer Acceptance, E-Sign & CBS Disbursement

Inter-Pool Choreography, Legal Signature SLA, CBS Transaction, and Reversal Compensation

Step Flow

Bank sends formal Sanction Letter to Applicant Pool. Applicant has 15 days to accept, followed by 48 hours to complete biometric e-Signature. On completion, the Transactional Disbursement Sub-process interacts with the Core Banking System (CBS) to disburse funds.

Completion
NEFT credited → SMS confirmation → End Event: "Loan Disbursed".
Task Types Used
Send Task
"Send Loan Sanction Offer" - Transmits formal contract terms to customer.
Receive Task
"Receive Offer Acceptance" - Awaits customer digital handshake.
User Task
"Execute Digital E-Signature" (Applicant) - Aadhaar/DocuSign cryptographic signing.
Service Tasks (CBS Sub-Process)
• "Penny-Drop Validation" • "Create CBS Loan Ledger" • "Execute NEFT Fund Transfer"
Gateways & Events
Boundary Timer (L9)
15-Day offer validity window; lapses offer if unaccepted by applicant.
Boundary Timer (L11)
48-Hour e-sign deadline; cancels application on non-execution.
Intermediate Compensation (L10)
Applicant withdrawal event triggers compensation to refund processing fee.
Boundary Error Event (L12)
Catches CBS 502/504 gateway timeout and routes to Operations hold queue.
Paths & Exceptions
Happy Path: Accepted in 24h → E-Signed → CBS ledger opened → Automated fund transfer success.
Payment Gateway Hold (L12): CBS API error holds funds → Ops conducts manual retry with 0 double debit risk.
Lapsed Offer (L9): 15-day timeout lapses sanction; reserved credit quota released.
Applicant Cancellation (L10): Compensation handler refunds origination fee to customer savings account.
